# Скилл: Формы с отправкой в Telegram-бота

Скилл собран на основе реальной анкеты на курс (июнь 2026), которая работает на Tilda. В шаблонах все личные данные заменены плейсхолдерами: `YOUR_BOT_TOKEN`, `YOUR_CHAT_ID`, `example.com`, `@your_username`.

## Что умеет скилл

- Создаёт **самодостаточный HTML-блок** (один файл, без зависимостей кроме Google Fonts)
- Шлёт заявки **в Telegram бота** через прямой fetch к api.telegram.org
- Совместим с Tilda T123 / Zero Block (компактная версия < 18 KB)
- Совместим с прямым хостингом на любом FTP (например, Beget)
- **Юридически правильный** блок согласий (3 галочки по требованию юриста РФ + 4 ссылки на документы в подвале)
- Условная логика полей (раскрытие доп. поля по выбранному варианту)
- Multi-select (несколько ответов), radio, текст, email
- Маска `@` для Telegram username с валидацией формата
- Адаптация под мобильные
- Стили подгоняются под бренд клиента

## Когда использовать

## Архитектура решения

### Стек
- **HTML5** + чистый **CSS** (без CSS-фреймворков) + **vanilla JS** (без jQuery, без зависимостей)
- **Шрифт**: Manrope с Google Fonts (для прямого хостинга) или Inter (для Tilda, локально без внешнего подключения — Manrope в РФ блокируется через Google Fonts проксированием)
- **Отправка**: прямой POST к `https://api.telegram.org/bot{TOKEN}/sendMessage`
- **Хранение**: в самом сообщении бота. CRM/Google Sheets не нужны для MVP

### Безопасность токена — важно
Во фронтенд-варианте токен бота **виден в исходном коде страницы**. Это риск, а не мелочь: тот, у кого есть токен, может не только слать сообщения от имени бота, но и читать входящие обновления (`getUpdates`), то есть видеть заявки с персональными данными, пока они не забраны. Поэтому:

- для одного бота — одна форма; бот только для заявок, без других функций;
- **никогда не коммить токен в git и не клади его в публичный репозиторий** — в шаблонах всегда `YOUR_BOT_TOKEN` / `YOUR_CHAT_ID`; настоящие значения подставляй только в копию, которую выкладываешь на сайт;
- не вписывай пароли и токены в файлы скилла — проси пользователя ввести их самому (например, скриптом, который спрашивает значение при запуске);
- если токен где-то засветился — сразу `/revoke` в @BotFather и обнови форму;
- **рекомендуемый вариант** для всего, что серьёзнее бесплатного лидмагнита: серверный прокси (PHP на хостинге, Cloudflare Worker, serverless-функция), где токен лежит в переменной окружения, а форма шлёт данные на свой endpoint.

## Юридический блок согласий — ОБЯЗАТЕЛЬНО

**По требованию юриста (РФ, 2026):** все 3 галочки должны быть **обязательными**, кнопка отправки **disabled** пока все 3 не отмечены.

### Текст галочек (не изменять без юриста)

1. **«Соглашаюсь с Политикой конфиденциальности»**
2. **«Соглашаюсь получать информационные и рекламные сообщения (рассылки в Telegram, email и других каналах)»**
3. **«Я согласен(а) на обработку моих персональных данных. С Политикой обработки персональных данных ознакомлен(а)»**

### Ссылки под галочками (3 шт)
- Политика конфиденциальности
- Согласие на получение информационных и рекламных сообщений
- Согласие на обработку персональных данных

### Ссылки в подвале страницы (4 шт)
То же, что выше, плюс:
- **Договор оферты** (нужен только в подвале, не в галочке, потому что для бесплатной формы оферта не активируется)

### Ссылки на документы (подставь свои)
- `https://example.com/privacy` — политика конфиденциальности
- `https://example.com/consent-personal-data` — согласие на обработку ПДн
- `https://example.com/consent-mailing` — согласие на рассылку
- `https://example.com/oferta` — договор оферты

### Почему именно так

Этот текст и структура согласий получены от практикующего юриста (РФ, июнь 2026). Это не юридическая консультация — для своего проекта согласуй тексты со своим юристом. Он покрывает:
- **152-ФЗ** «О персональных данных» — галочки 1 и 3
- **38-ФЗ** «О рекламе» статья 18 — галочка 2 (без неё нельзя слать маркетинговые рассылки)

**НЕ упрощай этот блок** до 1-2 галочек, даже если кажется избыточным. Это даёт владельцу формы законное право делать рассылки этим людям позже.

## Tilda-специфичные правила

### Лимит размера в T123 (HTML-блок)
~16 000–18 000 символов на блок. Если больше — используй **Zero Block → виджет HTML/Widget**.

### CSS-конфликты с Tilda
Tilda загружает свои стили (`tilda-grid`, `tilda-blocks-*`), которые **перебивают** твои. Решение:
- **Все CSS-правила с `!important`** — без исключений
- Все классы с префиксом `.anketa-` чтобы не конфликтовать со стилями Tilda
- Никаких сбросов `* { margin: 0 }` без `!important`
- Шрифт — `Inter` или системный, **не Manrope с Google Fonts** (Tilda не всегда корректно проксирует Google Fonts из РФ)

### Кэширование
После правки HTML-блока в Tilda нужно:
1. Нажать «Сохранить» в блоке
2. Нажать «Опубликовать» на странице
3. Подождать 1–2 минуты до обновления Tilda CDN
4. Открывать страницу с **Cmd+Shift+R** (hard reload) для проверки

### Подвал
Tilda сама управляет подвалом всей страницы. **Не вставляй footer с копирайтом в HTML-блок**, потому что он продублирует основной подвал сайта. **Только ссылки на документы** в самом блоке внизу — этого достаточно.

## Алгоритм работы скилла (по шагам)

Когда просят сделать форму:

### Шаг 1. Уточнить вопросы анкеты
Если список вопросов не дали — спросить:
- Какие поля собираем?
- Какие обязательные / опциональные?
- Какой тип у каждого поля (текст, email, выбор, мульти-выбор)?
- Есть ли условные поля (раскрытие по выбору)?

### Шаг 2. Получить технические данные
- **Токен Telegram-бота** (через @BotFather, инструкция ниже) — пользователь вставляет его сам, в репозиторий не коммитить
- **chat_id** получателя заявок (через @userinfobot или через `getUpdates` API)
- Куда заливаем: Tilda / свой хостинг по FTP / поддомен
- Какой стиль (попроси скриншоты сайта или дай палитру)

### Шаг 3. Создать бота (если нет)
Инструкция в файле `bot-setup-instruction.md`.

### Шаг 4. Сгенерировать HTML
- Полная версия для прямого хостинга
- Компактная версия для Tilda (`<18 KB`, с `!important`)

### Шаг 5. Залить или передать
- На свой хостинг — через `curl --user / ftp://...` (см. `deploy-via-ftp.md`)
- В Tilda — отдать файл, пользователь копирует его в T123 / Zero Block вручную

### Шаг 6. Протестировать
- Тестовая отправка через `curl` к Telegram API
- Заполнить форму в браузере и проверить что заявка пришла

## Telegram-бот: как создать

См. файл `bot-setup-instruction.md`.

Кратко:
1. @BotFather → `/newbot` → имя → username (обязательно `_bot`)
2. Получить токен
3. Найти своего бота в Telegram, нажать `/start`, отправить любое сообщение
4. Открыть `https://api.telegram.org/bot{TOKEN}/getUpdates` в браузере
5. Найти `"chat":{"id": ЦИФРЫ` — это chat_id

---

## Деплой по FTP (если форма не на Tilda; пример — Beget)

См. файл `deploy-via-ftp.md`.

Кратко:
1. В Beget создать **отдельный FTP-аккаунт** ограниченный одной папкой (никогда не давать главный пароль!)
2. Использовать curl: `curl -T file.html ftp://FTP_HOST/path/index.html --user FTP_USER` (пароль curl спросит сам — не пиши его в команду и в файлы)
3. Учесть: если основной домен проксируется на Tilda (через ddos-guard и т. п.), отдельные страницы с хостинга **под этим доменом не откроются** — нужен поддомен (`forms.example.com`) или другой домен

## Что НЕ делать

- ❌ **Не упрощать юридический блок** до 1 галочки — это нарушает 38-ФЗ и 152-ФЗ
- ❌ **Не хранить токен в Google-документе или публичном репо** — это утечка
- ❌ **Не использовать Google Forms** — он блокирован в РФ
- ❌ **Не подключать Google Fonts** напрямую в Tilda — могут не загрузиться. Использовать Inter или системные
- ❌ **Не давать главный пароль Beget для FTP-доступа** — всегда создавать отдельный FTP-аккаунт с ограничением папки
- ❌ **Не делать одну общую форму на все случаи жизни** — для каждой задачи (анкета, регистрация, обратная связь) свой шаблон
