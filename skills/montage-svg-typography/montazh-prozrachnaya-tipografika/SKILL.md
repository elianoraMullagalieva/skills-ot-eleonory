# Скилл: прозрачный субтитр-монтаж (kinetic-типографика)

## Приоритетное обновление · август 2026

Этот раздел **перекрывает любые противоречащие правила ниже**. Применять для всех новых роликов Эли.

1. Сначала HTML-превью 1080×1920 поверх исходного видео; рендер — только после одобрения.
2. Пословный синхрон обязателен: `mlx-whisper` с `word_timestamps=True`. Каждое слово появляется ровно в момент начала речи и остаётся до конца мысли. Никаких расчётов вида `start + index × 0.08`.
3. Главная типографика: максимум 1–2 слова крупно. Фразы из 3+ слов — только Onest Regular, строчными, без капса и без рукописи.
4. Рукописный шрифт допустим только для короткой подписи из 1–2 слов. Он не используется для основного смысла, перечислений и длинных фраз.
5. На одном кадре максимум заголовок + одна подпись либо две смысловые группы. Никаких 3–4 шрифтов, лесенок, гигантских многострочных блоков и случайной россыпи текста.
6. Размер зависит от длины фразы: длиннее фраза — меньше кегль и шире строка. Сначала сверить с 1080×1920, затем с вертикальным экраном телефона.
7. Белый текст без тени, обводки, blur, glow, `backdrop-filter` и полупрозрачных плашек. На прозрачном рендере фон пустой.
8. Перед вёрсткой снять контрольные кадры исходника и выбрать для белого текста тёмные свободные зоны. На белой одежде текст не размещать; переносить композицию, а не «спасать» тенью.
9. Порядок чтения всегда соответствует речи: слева направо и сверху вниз. Более поздняя фраза не может стоять выше ранней.
10. Стартовые анимации запускаются только после `video.play`; на нулевом кадре и при загрузке страницы текста быть не должно. Допустимы чистые opacity/translateY и короткая печатная машинка; запрещены blur-артефакты и zoom.
11. Перед сдачей: проверить нулевой кадр, все пословные таймкоды, 6–10 контрольных кадров, безопасные поля, отсутствие обрезки и контраст. Новые экспорты сохранять под новым именем, не перезаписывая утверждённые файлы.

Это ТЗ появилось на ролике «не делай это» (июль 2026). Эли монтирует его САМА поверх своего говорящего видео. Наша задача — сделать **прозрачный оверлей с субтитрами**, который ложится поверх кадра в такт речи. Следуй правилам дословно.

## ⭐ БЕЗОПАСНЫЙ СТИЛЬ ДЛЯ ПЕРЕДАЧИ
Для студенческих и коммерческих проектов используй только шрифты из папки `fonts/commercial-safe`: **Manrope** для основной типографики и **JetBrains Mono** для технических подписей. Они распространяются по лицензии SIL Open Font License 1.1; файлы лицензий лежат рядом со шрифтами.

- Заголовки: Manrope ExtraBold / Bold, строчными или капсом по задаче.
- Вторичный текст и списки: Manrope Regular / Medium.
- Технические подписи, теги, код: JetBrains Mono.
- Акцентный цвет выбирай из палитры конкретного ролика. На чёрном Screen-слое самый надёжный вариант — белый текст.

## 0. Что делаем
Текст-оверлей (HTML + anime.js) поверх видео Эли. Холст **1080×1920** (вертикаль). Фон прозрачный → в CapCut накладывается режимом **Screen (Экран)**.

**НЕ путать** с `eli-reels-graphics` — там полноэкранная SVG-подложка в квадрате. Здесь — субтитры-типографика поверх лица.

## 1. ЛАЙФХАК ЭКСПОРТА (главное)
Прозрачность через альфа-MOV капризна и медленна. **Рендерим на ЧИСТОМ ЧЁРНОМ фоне `#000`**, а в CapCut накладываем режимом **«Экран» (Screen)** — чёрный исчезает, остаётся текст.
- Путь в CapCut Desktop: выделить клип → правая панель, вкладка **«Видео»/«Основное»** (НЕ «Корректировка») → прокрутить вниз → **«Смешивание» / «Режим смешивания»** → **«Экран»**.
- Рендер: `record_v.py` (playwright video, РЕАЛЬНОЕ ВРЕМЯ = точный синхрон) в scratchpad. viewport 1080×1920, `background:#000`, `.panel{display:none}`, ffmpeg libx264 crf16.
- ⚠️ При параллельном рендере нескольких файлов — КАЖДОМУ своя temp-папка (`_vid_tmp_<stem>`), иначе перезапишут друг друга. Лучше рендерить последовательно.

## 2. ЦВЕТ — делать 2 варианта: БЕЛЫЙ и цветной
Через режим Screen **оранжевый/красный/лайм ложатся плохо** (мутно, грязно по краям — Эли забраковала). Поэтому:
- **Всегда делать чисто БЕЛУЮ версию** (весь акцент `#ffffff`) — она идеально чистая через Screen.
- Плюс цветную версию (акцент — красный `#e8412c` / лайм `#c6f33a`) на случай если фон под текстом тёмный.
- Отдавать оба файла, Эли выберет под свой кадр.
- Акцентный цвет брать из интерьера кадра (у Эли — красная неоновая лампа → `#e8412c`; для Кэмпа — лайм `#c6f33a`).

## 3. ТИПОГРАФИКА
- **Основной стиль — Manrope.** Заголовки: ExtraBold / Bold; вторичный текст и перечисления: Regular / Medium. Для премиального мягкого характера можно использовать строчные заголовки с умеренно плотным трекингом.
- **Технический акцент — JetBrains Mono.** Подходит для тегов, нумерации, терминов и коротких подписей.
- Используй максимум две гарнитуры в одном ролике. Длинную мысль дроби на смысловые строки вместо уменьшения текста до нечитаемого размера.
- `.label` — Manrope Medium, при необходимости uppercase, `letter-spacing: 0.08em–0.12em`, спокойный серо-белый цвет.

### 3.1 Типо-шкала (фиксированная, не прыгать)
```
hero    ~150–230px  (главное слово кадра)
hero.xl ~300px      (одиночный акцент: цифра, «УРОК»)
hero.sm ~112–150px  (заголовок сцены с контентом)
script  ~90–120px   (рукопись Gogol)
label   ~42px       (вводная строка / нумерация ошибок)
```
Заголовок и мелкий текст НЕ могут быть почти одного размера — иерархия обязательна.

## 4. КОМПОЗИЦИЯ
- **Зона текста — верхняя половина**, центр ~330–950px (над лицом Эли, низ кадра свободен). Не впритык к верху, дать воздух сверху ~330px.
- **ВСЁ по центру** (flex column, align-items:center) — единая система. Исключение: перечисления/шаги/списки — по ЛЕВОМУ краю единым блоком (заголовок тоже слева).
- **Строки одной сцены — ВПЛОТНУЮ** (`gap:0`, `line-height~.9`, отрицательные margin между строками hero). Большой зазор = «дыра», Эли забраковала.
- Многослойная композиция допустима (белое слово наезжает на большое цветное — как «НЕ ДЕЛАЙ ЭТО»: гигантское цветное «НЕ» сверху, белое «ДЕЛАЙ ЭТО» под ним внахлёст, рукопись снизу).
- **НЕ 3 разных текста рядом** (Эли забраковала «да,нравится→ЦЕНА→и она заходит адекватно» — перегруз). Максимум заголовок + 1 рукопись/вводная. Лишнее — на отдельный слайд или убрать.

## 5. АНИМАЦИЯ ПОЯВЛЕНИЯ (без zoom!)
- **ЗАПРЕЩЕНА «зумка»** — появление через `scale` (то увеличивается, то отдаляется). Эли забраковала. Только `opacity` + мягкий `translateY` снизу (`easeOutQuart`, 450–480мс).
- **Рукопись — эффект «дописывания»**: `clipPath:['inset(0 100% 0 0)','inset(0 0% 0 0)']` слева направо + лёгкий translateY. Длительность под длину фразы (короткая 450мс, длинная до 1900мс — «медленнее прописывать»).
- Открытие «складывается по очереди»: слово 1 → слово 2 → рукопись, каждое со своим delay.
- Чипсы-теги влетают по одному (opacity+translateY), можно лёгкий rotate. Платформы (Behance/Pinterest…) — ЗАГОРАЮТСЯ акцентом по одной, когда Эли их называет.
- Стрелка «в описании» — маленькая, аккуратная, появляется ПОСЛЕ слова, покачивается (translateY loop).

## 6. СИНХРОН — САМОЕ ВАЖНОЕ (правила выверены Эли)
Whisper (`mlx-whisper`, `whisper-large-v3-turbo`, PATH `~/Library/Python/3.9/bin`, `--word-timestamps`) → берём ПОСЛОВНЫЕ таймкоды.

**Правила синхрона (жёсткие):**
1. **Слово появляется В МОМЕНТ, когда Эли начинает его говорить** — не раньше. Считать delay элемента = (таймкод_слова − таймкод_старта_сцены)×1000 мс.
2. **Конец не обязан совпадать** — слову дать **+0.5с постоять** после, даже если Эли сразу говорит дальше. Успеть прочитать важнее.
3. **НИ ОДНОЙ паузы ≥1.5с без текста.** Если длинная фраза речи (>4с) на одной сцене — заполнять: вводная строка (label) в начале + промежуточные пункты по мере речи + финал. Пример: «объединила знания, как нахожу, продвигаюсь, продаю, в один урок» → пункты «нахожу клиентов / и продвигаюсь / и продаю» появляются по очереди → схлопываются в «УРОК».
4. **Порядок = порядок речи.** Платформы, пункты — строго как названы (Behance→Deep Profile→Pinterest→Awwwards, а не как удобно).
5. **Ни одна фраза не теряется.** Если в речи «даже самому состоятельному клиенту будет дорого, если сразу назвать цену» — показать ВСЁ: вводная «даже состоятельному» (label) → «ДОРОГО» (hero) → «если сразу назвать цену» (рукопись). Не выкидывать вводную и не обрезать концовку.
6. Загорание/смена акцента — быстро (200мс), ровно на слове.

**Реализация:** rAF-плеер, массив `CUES=[[sec, en_fn],...]` — старт каждой СЦЕНЫ. Внутри сцены элементы через `delay` (в мс от старта сцены) под пословные таймкоды. Проверять интервалы между CUES: сцена держится всю свою фразу, первый элемент сцены — не позже +1.5с от старта.

## 7. ПАЙПЛАЙН
1. Транскрипт whisper → пословные таймкоды.
2. Разложить речь на сцены (1 мысль = 1 сцена), составить CUES + список акцентных фраз.
3. Собрать HTML (шаблон-структура: `.zone` top:330, `.scene` flex-center, типо-шкала, хелперы `rise/fadeIn/write/show`, rAF-плеер). Чёрный фон.
4. Проверять СНИМКАМИ через playwright (быстро, не рендерить видео на каждую правку) — но тайминги внутри сцены проверять отдельным прогоном `en_sN()` с `wait_for_timeout`.
5. Утвердить у Эли (открыть HTML в браузере — она смотрит движение живьём; кнопка переключения фон чёрный/превью-видео).
6. Рендер `record_v.py` → mp4 (чёрный фон). Делать БЕЛУЮ + цветную версии. Если 2 длины ролика (полная/сокращённая) — обе.
7. Проверить синхрон рендера по кадрам на таймкодах речи (симулировать Screen: `ImageChops.screen`).
8. Сохранить результат в согласованную папку проекта и объяснить наложение через Screen.

## 9. ПРОЗРАЧНЫЙ ЭКСПОРТ (Эли предпочла альфу, Screen лагал/мутил)
Screen-наложение оказалось капризным (лагало в CapCut, оранжевый/лайм мутнели по краям). **Надёжный прозрачный вывод — ProRes 4444 с альфой** через `record_alpha2.py` (в scratchpad):
- Снимает прозрачные скриншоты (`omit_background=True`), каждый метит ФАКТИЧЕСКИМ временем анимации (`performance.now`), затем ffmpeg concat с реальными длительностями → синхрон ТОЧНЫЙ (в отличие от `page.clock`, который спешил — НЕ использовать clock для альфы).
- ffmpeg: `-c:v prores_ks -profile:v 4444 -pix_fmt yuva444p10le`.
- Файл тяжёлый (~200 МБ на 45с) — это норма для ProRes-альфы. Эли кидает прямо на дорожку, режим смешивания НЕ нужен.
- Всё равно полезно отдавать и лёгкую Screen-mp4 (чёрный фон) как запасной вариант.

### 9.1 Баги прозрачного рендера (проверять всегда!)
- **`backdrop-filter:blur` + полупрозрачный фон на альфе = «белые круги»** без текста (Эли забраковала чипсы). На прозрачной версии чипсы делать: `background:transparent; border:3px solid #fff; color:#fff` (обводка + чёткий текст), БЕЗ backdrop-filter и без rgba-заливки.
- Чипсы, которые «загораются» акцентом — при загорании заливаются цветом (`backgroundColor:LIME/red`, текст тёмный). На прозрачном это ок.
- **❌ ФОНОВАЯ dot-сетка (canvas #dotgrid, полупрозрачная) = точки по ВСЕМУ кадру после экспорта** (29.07 Эли: «блядские белые точки во весь экран», в т.ч. на лице). В редакторе на превью почти не видна (opacity .35), но при экспорте проявляется везде. **НА ПРОЗРАЧНОЙ ВЕРСИИ ФОНОВУЮ СЕТКУ НЕ ВКЛЮЧАТЬ ВООБЩЕ** (`#dotgrid{display:none}`, не вызывать drawGrid). Точки должны быть ТОЛЬКО в локальной инфографике (particleField в конкретной sceneB), а не сплошным фоном на весь кадр. Любой полупрозрачный фоновый слой (сетка, дымка, виньетка) на альфа-версии = мусор поверх видео Эли. Правило: на прозрачном оверлее НИЧЕГО не должно быть за пределами явных текст/графика-элементов — фон строго пустой.

### 9.2 НЕ ТЕРЯТЬ ФРАЗЫ (Эли ловила пропажи)
Каждую значимую фразу речи показать. Частые потери и как чинить:
- «Второе — **продавать** в переписке» → показать И «продавать» И «в переписке» (2 строки, в v2-стиле строчными). Не только «в переписке».
- «даже самому состоятельному клиенту **будет дорого**» → Эли выбрала: **«будет / дорого» две КРУПНЫЕ строки одинакового размера**, снизу мелко рукописью «если сразу назвать цену». (Не мелкая вводная + одно «дорого».)
- «И я **объединила эти знания**, как нахожу…, как продаю, в один урок» → показать вводную «объединила знания» → список пунктов по речи → схлопнуть в «УРОК». Не выкидывать «объединила».
- Длинную перечислительную фразу (нахожу/продвигаюсь/продаю) — пунктами по мере называния, потом финал-схлопывание. Заполняет паузу и ничего не теряет.

### 9.3 ВЕРСИОНИРОВАНИЕ ФАЙЛОВ (Эли монтирует параллельно — НЕ ломать её нарезку!)
- **НИКОГДА не удалять и не перезаписывать файл, который Эли уже могла нарезать.** Она монтирует в реальном времени; перезапись по тому же пути рушит её таймлайн (CapCut теряет привязку). Инцидент 28.07: удалила оранжевый файл → у Эли слетела нарезка.
- Новую версию сохранять под НОВЫМ именем (`-НОВАЯ`), старую оставлять под исходным именем нетронутой.
- При параллельном рендере нескольких файлов — каждому своя temp-папка (`_vid_tmp_<stem>` / `_alpha_<stem>`), иначе перезапишут друг друга (был баг: белая и оранжевая вышли идентичными). Надёжнее — последовательно.
- Если CapCut лагает на воспроизведении — перекодировать в CapCut-friendly (`-g 25 -keyint_min 25 -sc_threshold 0 -movflags +faststart`), сохранить как отдельную `-гладкий` копию.

## 8. ЧЕК-ЛИСТ ПЕРЕД СДАЧЕЙ
- [ ] Каждое слово появляется когда Эли его говорит (не раньше)
- [ ] Нет пауз ≥1.5с без текста
- [ ] Ни одна фраза речи не потеряна, вводные и концовки на месте
- [ ] Порядок элементов = порядок речи
- [ ] Рукопись ≤3-4 слов, не режется по низу, успевает прописаться +постоять
- [ ] Нет «зумки», только opacity+translateY
- [ ] Строки вплотную, нет «дыр»
- [ ] Иерархия размеров (заголовок ≠ мелкий текст)
- [ ] Не 3 текста рядом
- [ ] Стиль по умолчанию = Manrope + JetBrains Mono из папки `fonts/commercial-safe`
- [ ] Прозрачный ProRes-альфа рендер (chipsы БЕЗ backdrop-filter — обводкой!)
- [ ] НЕ перезаписан файл, который Эли уже нарезала (новая версия = новое имя)
- [ ] Синхрон проверен по кадрам рендера (по номеру кадра, не -ss на VFR)
