# Как сохранить скилл в память Клода

**Что это:** Способ сохранить правило, контекст проекта или предпочтение так, чтобы Claude помнил это в следующих разговорах

**Когда использовать:** Когда не хочется повторять одно и то же каждый раз — правила клиента, фирменный стиль, запреты, контекст проекта

---

## Что такое память Claude и где она хранится

Claude не помнит предыдущие разговоры автоматически. Но есть специальные файлы-записки — они лежат здесь:

```
~/.claude/projects/-Users-elianora/memory/
```

Там может быть несколько .md файлов. Главный — MEMORY.md, он как оглавление: содержит список всего что запомнено и ссылки на отдельные файлы.

Каждый новый разговор Claude читает эти файлы и знает контекст — проекты, клиентов, правила, предпочтения.

---

## Как попросить Claude запомнить правило, клиента, проект

Просто скажи это прямо:

```
Запомни: у клиента Диана нельзя использовать капс в заголовках.
Она принципиально против. Записать в память.
```

```
Запомни контекст проекта Performance Club:
- фирменный цвет: #1A1A2E
- тон голоса: строгий, без юмора
- формат видео всегда 16:9
Сохрани в память как отдельный файл.
```

```
Запомни моё правило: все заголовки на сайте — не более 7 слов.
Проверять автоматически когда я прошу написать текст для лендинга.
```

---

## Формат файла памяти

Файлы памяти — обычные markdown с понятным содержимым. Claude сам создаёт структуру, но ты можешь попросить конкретный формат:

```markdown
# Название файла памяти

**Тип:** project / user / reference / feedback
**Создан:** дата
**Проект:** название если относится к проекту

## Что запомнено

[содержимое]
```

Файл попадает в папку memory и строка появляется в MEMORY.md с кратким описанием.

---

## Типы памяти

**user** — личные предпочтения и правила Элианоры:
"Я не использую Notion, только Figma и Claude. Не предлагать Notion."

**project** — контекст конкретного проекта:
"Design Camp: аудитория — дизайнеры 25-35, боль — нет системы, хотят структуру"

**reference** — справочная информация которая нужна снова и снова:
"Фирменные цвета DERZAY: основной #FF4D00, фон #F3F3F3, текст #1C1C1C"

**feedback** — что сработало или не сработало:
"Промпт с caustic light refraction дал лучший результат для стеклянных фигур"

---

## Пример: "запомни что у клиента X нельзя использовать капс"

```
Запомни в память (тип: project):
Клиент: Диана, проект Design Camp
Правило: никогда не использовать КАПС в заголовках и кнопках.
Это принципиальная позиция клиента, не обсуждается.
При написании любых текстов для этого проекта — проверять автоматически.
```

После этого в новом разговоре достаточно сказать "пишу текст для Design Camp" — и Claude уже знает про запрет капса.

---

## Как потом найти и прочитать сохранённый скилл

Посмотреть что вообще запомнено:

```
Покажи что у тебя сохранено в памяти. Список всех файлов.
```

Прочитать конкретный файл:

```
Прочитай из памяти файл про проект Performance Club
```

Найти правило:

```
Есть ли у меня в памяти что-то про типографику?
```

Или открыть прямо в Finder:
`Cmd + Space` → вбить `~/.claude/projects/-Users-elianora/memory/` → Enter

---

## Лайфхаки и правила

- Давай файлам памяти говорящие имена — "project_design_camp.md" лучше чем "memory1.md"
- Проси обновить память когда что-то изменилось: "обнови в памяти — теперь у клиента другой цвет бренда"
- Память читается в начале разговора — не нужно каждый раз объяснять контекст
- Можно хранить в памяти удачные промпты: "запомни этот промпт для стеклянных фигур как рабочий шаблон"

---

## Частые ошибки

- Думать что Claude запомнит сам без явной просьбы — не запомнит, нужно прямо попросить "запиши в память"
- Хранить всё в одном большом файле — лучше отдельные файлы по проектам, их легче обновлять
- Не проверять что память обновилась — попроси Claude подтвердить: "прочитай что записал"
- Забывать обновлять память когда проект меняется — устаревший контекст хуже чем отсутствующий
