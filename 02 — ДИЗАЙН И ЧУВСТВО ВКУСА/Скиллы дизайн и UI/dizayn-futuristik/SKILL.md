# Дизайн Футуристик

Универсальная методичка для дизайна и вёрстки футуристичных проектов в стиле Apple / Awwwards / Linear / Aesop / Addverb. Не Кэмп-специфичная, применима к любому продукту, где нужен тихий дорогой футуризм.

Этот скилл написан **на ошибках**, которые я уже совершила в проектах. Каждое правило идёт с примером «было плохо → стало хорошо», чтобы можно было сверять.

---

## 1. ЖЁСТКИЕ ЗАПРЕТЫ (если хоть одно — макет переделывать)

### 1.1 Композиция и сетка
- **Запрещено**: фиксированные абсолютные координаты без масштабирования контейнера. Это приводит к обрезанию правых карточек, когда окно браузера меньше 1920px.
- **Решение**: оборачивать всю фигма-сцену 1920×N в `.stage > .stage__scaled` и через `transform: scale(window.innerWidth / 1920)` подгонять под окно. Высота `.stage` пересчитывается. Так пропорции остаются 1:1 как в Figma, и ничего не обрезается.
- **Запрещено**: «три одинаковые колоночки» как сетка раздела «фичи / преимущества / тарифы». Это самый дешёвый паттерн.
- **Решение**: bento-сетка с **разными** размерами ячеек (1×1, 1×2, 2×1, 2×2, 3×1) и **разной** плотностью контента (где число, где иллюстрация, где длинный текст, где цитата, где график).
- **Запрещено**: симметричные сетки везде. Если левая колонка 286 — правая не должна быть тоже 286. Ломать симметрию через 286 vs 240, или 580/480/620 вместо 540/540/540.
- **Запрещено**: ячейки одинакового структурного шаблона (везде «тэг + заголовок + большая цифра + подпись»). После трёх таких ячеек становится скучно.

### 1.2 Типографика
- **Запрещено**: hero-заголовок шрифтом > 64px, который не помещается в одну строку и переносит слово на третью строку. Слова `работой`, `справляется`, `технологии` — длинные, легко улетают.
- **Решение**: до публикации **проверить визуально** ширину слов при текущем fontSize/letter-spacing. Если переносится — уменьшить размер ИЛИ разбить на короткие фразы.
- **Запрещено**: один и тот же sans-serif для заголовка, бренда и body. Слишком стерильно.
- **Решение**: акцентный serif (Instrument Serif, Source Serif, PP Editorial New, Mondwest) для бренда и одного выделенного слова в hero-заголовке курсивом. Остальное — Inter / Geist / Plus Jakarta Sans.
- **Запрещено**: ВЕРХНИЙ РЕГИСТР на заголовки. Только на eyebrow-метки (`02 · ВОЗМОЖНОСТИ`).
- **Запрещено**: «висячие» слова — одно слово на последней строке заголовка («работой» одно).
- **Запрещено**: тексты, наезжающие друг на друга. Особенно в bento-карточках, где big-число фиксированно прибито к низу, а длинный сабтекст переносится — они встречаются посередине.
- **Решение**: использовать flex/grid + `gap`, а не абсолютные `bottom: 80px` + `top: 56px`.

### 1.3 Карточки и фон
- **Запрещено**: белые карточки `#fff` с тенью на почти-белом `#f9fcf9` — они не «парят», а торчат.
- **Решение**: либо чуть более тёплый фон (#f5f3ef, #ececec, #f6f8f6), либо карточки с `background: rgba(255,255,255,.92)` + `backdrop-filter: blur(12px)` + хайрлайн `border: 1px solid rgba(255,255,255,.6)`.
- **Запрещено**: тяжёлые тёмные тени `0 20px 40px rgba(0,0,0,.3)`. Сразу читается как «бутстрап».
- **Решение**: двойная тень с малой непрозрачностью: `0 1px 1px rgba(10,10,10,.04), 0 12px 28px rgba(10,10,10,.10)`.
- **Запрещено**: одинаковые radius на всех карточках. Делать большие 28px и маленькие 24px, чтобы был ритм.

### 1.4 Цифры и диаграммы
- **Запрещено**: плоская цифра без визуального подкрепления («96%», «128+», «3 года» без графика). Это самый частый недостаток AI-дизайнов.
- **Решение**: каждое крупное число подкреплено диаграммой:
  - процент → донат / арка из точек / линейный прогресс
  - количество → бары / эквалайзер / sparkline
  - срок (годы) → горизонтальный таймлайн с тиками
  - скорость → sparkline времени отклика
  - количество интеграций → радиальная диаграмма со связями
- **Запрещено**: непонятный смысл «96% чего». Всегда подпись под числом: «оптимизация дома», «точность распознавания», «безотказная работа».

### 1.5 Hero-секция конкретно
- **Запрещено**: nav без фона на полупрозрачном фоне видео — текст nav сливается с изображением.
- **Решение**: nav на градиенте от непрозрачного фона страницы к прозрачному `linear-gradient(to bottom, var(--bg) 60%, transparent)`.
- **Запрещено**: hero-заголовок поверх лица робота / главного объекта на фото. Текст должен быть либо НАД верхней частью объекта (сверху), либо в боковой композиции.
- **Решение**: для центрированного фото с лицом — текст в верхней трети + мягкое затемнение видео сверху (gradient mask), чтобы текст читался.
- **Запрещено**: «↔ Двигайте мышью»-подсказка появляется через 0.5s. Слишком навязчиво.
- **Решение**: появляется через 3+ секунды после загрузки, маленьким серым шрифтом, под основным объектом, capslocked.

### 1.6 Плейсхолдеры и фото
- **Запрещено**: пустые серые квадраты вместо фото в финальном макете. Это болванка, а не дизайн.
- **Решение**: всегда хотя бы попытаться вставить реальное фото или иллюстрацию. Если технически не получается (как у меня с base64-лимитом 50K в `use_figma`) — разрезать на чанки, использовать `figma.createImage(Uint8Array)` через несколько вызовов, или подсунуть мини-копию 500px в base64.
- **Запрещено**: на тёмном фоне светлые карточки с зашкварным белым `#fff` — слишком резкий контраст. Тёплый off-white `#f0ede8`.

## 2. АНИМАЦИЯ — ПРАВИЛА (для футуристичных лендингов)

### 2.1 Принцип последовательности
- **Запрещено**: всё анимируется одновременно при загрузке. Зритель не успевает считать.
- **Решение**: stagger между блоками 120-200ms. Между словами заголовка 80-120ms. Между карточками 150-200ms.

### 2.2 Принцип постоянной микро-динамики
- **Запрещено**: статичный макет после загрузки. «Дорого» — значит макет дышит даже когда пользователь не двигается.
- **Решение**: 3-5 фоновых бесконечных лупов:
  - пульсирующие точки-индикаторы (3s ease-in-out, scale + opacity)
  - вращение колец точек (40-60s linear)
  - дыхание баров эквалайзера (3.8s)
  - вращение часовой стрелки в иконках (8s)
  - shimmer-полосы по периметру карточек (14s linear)

### 2.3 Принцип счётчиков по очереди
- **Запрещено**: все цифры (96%, 128+, 2ч, 3 года) запускают счётчик одновременно.
- **Решение**: каждый счётчик стартует со своим delay, последовательно по визуальному маршруту глаза (например слева сверху → слева снизу → справа сверху → справа снизу): 1100ms, 1450ms, 1750ms, 2050ms.

### 2.4 Принцип реакции на курсор
- **Видео-фон со scrub по мышке**: позиция курсора X на окне (0→1) маппится в `video.currentTime` (0→duration). Плавная интерполяция через lerp 0.10-0.15. При уходе курсора возвращается в центр.
- **Параллакс карточек**: при mousemove карточки сдвигаются на 6-8px в противоположную сторону от курсора. Карточки переднего плана глубже (depth +8), задние мельче (depth ±4).
- **Hover на карточке**: лёгкое поднятие `translateY(-4px)` + углубление тени за 600ms ease cubic-bezier(.22,1,.36,1).

### 2.5 Принцип easing
- **Запрещено**: `linear`, `ease`, `ease-in-out` для UI-переходов.
- **Решение**: `cubic-bezier(.22,1,.36,1)` (премиум-выход), `cubic-bezier(.45,.05,.25,1)` (мягкое возвращение).

### 2.6 Reduced motion
- Всегда `@media (prefers-reduced-motion: reduce)` с обнулением длительностей. Это не опция, это норма.

## 3. ТЕХНИЧЕСКИЕ ПРАВИЛА ВЁРСТКИ (no-trash)

### 3.1 Резиновость без обрезаний
```css
.stage{
  width: 100vw;
  height: calc(100vw * SCENE_H / SCENE_W);  /* пропорция Figma */
  overflow: hidden;
}
.stage__scaled{
  position: absolute;
  width: SCENE_W; height: SCENE_H;
  transform-origin: top left;
}
```
И в JS:
```js
function resize(){
  const scale = innerWidth / SCENE_W;
  scaled.style.transform = `scale(${scale})`;
  stage.style.height = `${SCENE_H * scale}px`;
}
```

### 3.2 SVG-диаграммы программно
Кольца точек, дуги, sparkline и таймлайны рисовать через `document.createElementNS('http://www.w3.org/2000/svg','circle')` в цикле, а не вручную ставить 36+ эллипсов в HTML. Меньше кода, легче править.

### 3.3 Видео для scrub
- Видео должно быть короткое: 5-15 сек, 24-30fps, без аудио.
- Кодек: H.264 baseline, не HEVC (для iOS Safari).
- Размер файла: до 12 MB для hero. Использовать `ffmpeg -vcodec libx264 -crf 23 -preset slow` для оптимизации.
- Атрибуты: `muted playsinline preload="auto" loop`.
- В JS: `video.pause()` после loadedmetadata, дальше управление через `video.currentTime`.

### 3.4 Шрифты
- Подключение через Google Fonts с `preconnect` для перформанса.
- `font-display: swap` всегда.
- Для премиум-настроения добавить serif (Instrument Serif или PP Editorial New) к Inter — даже одно слово курсивом в hero-заголовке работает.

### 3.5 Цветовая логика
- Один акцент на всю секцию. Если янтарь — то везде только янтарь. Если бирюза — то только бирюза. **Никогда не миксовать янтарь + бирюзу в одной секции**.
- 5 оттенков ink: `#0a0a0a` (strong), `#1a1a1a` (default), `#666666` (mid), `#8a8a8a` (sub), `#c7c7c7` (low). Хватает на все типографические слои.
- Фон: тёплый off-white `#f5f3ef` / `#f6f8f6` / `#f9fcf9`, никогда чистый `#ffffff` или чистый `#000000`.

## 4. ЧЕК-ЛИСТ ПЕРЕД ВЫДАЧЕЙ МАКЕТА/ВЁРСТКИ

Прогнать каждый пункт. Если хоть один проваливается — переделать, **не выдавать**.

### Композиция
- [ ] При окне 1280px все элементы видны полностью, ничего не обрезается
- [ ] При окне 1920px пропорции совпадают с Figma 1:1
- [ ] Нет «трёх одинаковых колонок» нигде
- [ ] Ячейки в bento разной плотности и структуры
- [ ] Симметрия нарушена хотя бы один раз

### Типография
- [ ] Hero-заголовок помещается без переноса длинного слова на отдельную строку
- [ ] Нет висячих слов
- [ ] Есть serif-акцент (хотя бы в бренде или одном слове)
- [ ] Нет ВЕРХНЕГО РЕГИСТРА на заголовках
- [ ] Все большие числа `tabular-nums` (моноширинные)

### Карточки и контраст
- [ ] Карточки с blur-фоном, а не белые-белые на белом
- [ ] Тени мягкие, двухслойные, не тёмные
- [ ] Текст внутри карточек НЕ наезжает на цифры

### Цифры и диаграммы
- [ ] Каждое крупное число подкреплено визуальной диаграммой
- [ ] У каждого числа есть осмысленная подпись («чего именно 96%»)
- [ ] Диаграммы рисуются программно SVG, не картинками

### Фото и плейсхолдеры
- [ ] В финальном макете нет пустых серых квадратов
- [ ] Текст hero не наезжает на лицо главного объекта на фото
- [ ] Видео-фон затемнён сверху градиентом под заголовок

### Анимация
- [ ] Stagger между блоками 120-200ms
- [ ] Цифры запускаются по очереди, не одновременно
- [ ] Есть 3+ постоянных фоновых лупа после загрузки
- [ ] Все easing — cubic-bezier, не linear/ease
- [ ] prefers-reduced-motion обрабатывается
- [ ] Если на странице видео — реакция на курсор реализована
- [ ] Hover на карточках поднимает на 4px, не на 12px

### Технические
- [ ] Сцена обёрнута в `.stage > .stage__scaled` с динамическим scale
- [ ] Видео ≤12 MB, H.264, preload="auto"
- [ ] Шрифты через preconnect + font-display: swap
- [ ] Один акцентный цвет на секцию

## 5. РЕФЕРЕНСЫ ТОНА

Куда смотреть, чтобы поймать «футуристик-премиум»:
- **Apple Vision Pro / Apple Watch product pages** — для иерархии и тихой типографики
- **Linear.app** — для bento-сеток и тонких границ
- **Aesop / Apple Aesop-style editorial** — для бежевой палитры и serif-акцентов
- **Addverb Robotics / Scout AI** — для тёмной кинематографичной hero-секции
- **Standard Bots** — для bento brutalist
- **Awwwards SOTD за последние 6 месяцев** — для motion и реактивности
- **Botronics, Figure AI, 1X Technologies** — для роботических hero с видео

Что **никогда не использовать как референс**:
- Bootstrap-страницы
- Stripe.com (он хорош, но это уже AI-default)
- Любые сайты с фиолетовыми AI-градиентами

## 6. КАК ПРИМЕНЯТЬ

1. **Перед стартом** — прочитать этот файл целиком.
2. **Во время дизайна/вёрстки** — держать чек-лист открытым, сверяться по каждому пункту по мере добавления секций.
3. **Перед выдачей результата** — пройти весь чек-лист главы 4 ещё раз. Если есть «нет» — переделать.
4. **После работы** — если выявилась новая ошибка, не описанная здесь — дополнить главу 1 новым правилом с примером.

Этот скилл должен **расти** с каждым проектом. Эли и я будем дополнять его правилами после каждого факапа.
