# Скилл: Формы с отправкой в Telegram-бота

Скилл собран на основе реальной анкеты для Дизайн Кэмпа (июнь 2026), которая успешно работает на `derzayvdesign.com/anketa-camp`.

## Что умеет скилл

- Создаёт **самодостаточный HTML-блок** (один файл, без зависимостей кроме Google Fonts)
- Шлёт заявки **в Telegram бота** через прямой fetch к api.telegram.org
- Совместим с Tilda T123 / Zero Block (компактная версия < 18 KB)
- Совместим с прямым хостингом на Beget / любом FTP
- **Юридически правильный** блок согласий (3 галочки по требованию юриста РФ + 4 ссылки на документы в подвале)
- Условная логика полей (раскрытие доп. поля по выбранному варианту)
- Multi-select (несколько ответов), radio, текст, email
- Маска `@` для Telegram username с валидацией формата
- Адаптация под мобильные
- Стили подгоняются под бренд клиента

## Архитектура решения

### Стек
- **HTML5** + чистый **CSS** (без CSS-фреймворков) + **vanilla JS** (без jQuery, без зависимостей)
- **Шрифт**: Manrope с Google Fonts (для прямого хостинга) или Inter (для Tilda, локально без внешнего подключения — Manrope в РФ блокируется через Google Fonts проксированием)
- **Отправка**: прямой POST к `https://api.telegram.org/bot{TOKEN}/sendMessage`
- **Хранение**: в самом сообщении бота. CRM/Google Sheets не нужны для MVP

### Безопасность токена
Токен бота **виден в исходном коде страницы** (это нельзя избежать в чисто-фронтенд решении). Максимум, что может сделать злоумышленник — отправить себе же сообщение через бота. **Реального вреда нанести нельзя**, потому что бот может только писать в chat_id, который пользователь указал заранее (свой). Это приемлемо для бесплатных лидмагнитов и анкет.

**Когда нужна полная безопасность** (например, оплачиваемые формы) — делать через серверный endpoint (PHP на Beget, Cloudflare Worker, или Node.js хостинг), где токен в env-переменной. Это уровень «парковка» — добавляем когда форма реально начинает приносить деньги.

## Юридический блок согласий — ОБЯЗАТЕЛЬНО

**По требованию юриста (РФ, 2026):** все 3 галочки должны быть **обязательными**, кнопка отправки **disabled** пока все 3 не отмечены.

## Tilda-специфичные правила

### Лимит размера в T123 (HTML-блок)
~16 000–18 000 символов на блок. Если больше — используй **Zero Block → виджет HTML/Widget**.

### CSS-конфликты с Tilda
Tilda загружает свои стили (`tilda-grid`, `tilda-blocks-*`), которые **перебивают** твои. Решение:
- **Все CSS-правила с `!important`** — без исключений
- Все классы с префиксом `.anketa-` чтобы не конфликтовать со стилями Tilda
- Никаких сбросов `* { margin: 0 }` без `!important`
- Шрифт — `Inter` или системный, **не Manrope с Google Fonts** (Tilda не всегда корректно проксирует Google Fonts из РФ)

### Кэширование
После правки HTML-блока в Tilda нужно:
1. Нажать «Сохранить» в блоке
2. Нажать «Опубликовать» на странице
3. Подождать 1–2 минуты до обновления Tilda CDN
4. Открывать страницу с **Cmd+Shift+R** (hard reload) для проверки

### Подвал
Tilda сама управляет подвалом всей страницы. **Не вставляй footer с копирайтом DD Academy в HTML-блок**, потому что он продублирует основной подвал сайта. **Только ссылки на документы** в самом блоке внизу — этого достаточно.

## Telegram-бот: как создать

См. файл `bot-setup-instruction.md`.

Кратко:
1. @BotFather → `/newbot` → имя → username (обязательно `_bot`)
2. Получить токен
3. Найти своего бота в Telegram, нажать `/start`, отправить любое сообщение
4. Открыть `https://api.telegram.org/bot{TOKEN}/getUpdates` в браузере
5. Найти `"chat":{"id": ЦИФРЫ` — это chat_id

---

## Деплой на Beget (если форма не на Tilda)

См. файл `deploy-via-ftp.md`.

Кратко:
1. В Beget создать **отдельный FTP-аккаунт** ограниченный одной папкой (никогда не давать главный пароль!)
2. Использовать curl: `curl -T file.html ftp://elianora21.beget.tech/path/index.html --user USER:PASS`
3. Учесть: домен `derzayvdesign.com` проксируется через ddos-guard → Tilda, поэтому прямой Beget-хостинг отдельных страниц **не работает под этим доменом** — нужен или поддомен (`camp.derzayvdesign.com`) или другой домен (`yanadlx.ru`)

## Что НЕ делать

- ❌ **Не упрощать юридический блок** до 1 галочки — это нарушает 38-ФЗ и 152-ФЗ
- ❌ **Не хранить токен в Google-документе или публичном репо** — это утечка
- ❌ **Не использовать Google Forms** — он блокирован в РФ
- ❌ **Не подключать Google Fonts** напрямую в Tilda — могут не загрузиться. Использовать Inter или системные
- ❌ **Не давать главный пароль Beget для FTP-доступа** — всегда создавать отдельный FTP-аккаунт с ограничением папки
- ❌ **Не делать одну общую форму на все случаи жизни** — для каждой задачи (анкета, регистрация, обратная связь) свой шаблон
