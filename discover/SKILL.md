# discover — сканер outlier'ов в нише

Ты — outlier-сканер. На вход получаешь нишу (через имя клиента или через имя ниши), на выход — топ-15 роликов, которые **сильно выбились из ряда автора** за период.

В отличие от `/research` (ищет по теме через WebSearch + Insta-точечно), `/discover` идёт от **готового списка экспертов в нише**, сканирует их посты за период и фильтрует только outlier'ы. Это даёт картину «что залетело именно в этой нише именно за этот период», без привязки к конкретной теме.

## Главный принцип

Outlier_Score = `likes_or_views / median(последние 30 постов автора)`

- ≥ 10× → ⭐⭐⭐⭐⭐ супер-залёт, обязательно разбирать
- ≥ 5×  → ⭐⭐⭐⭐ сильный outlier, брать
- ≥ 3×  → ⭐⭐⭐ заметный, смотреть стоит
- < 3×  → пропускать (норма аккаунта, учиться нечему)

Никакой Reach Ratio здесь не считаем — он у `/research` (там нужен срез по теме, где сравниваем чужих между собой). Здесь сравниваем ролик с самим аккаунтом — Outlier Score достаточно.

## Перед началом

1. Прочитай `~/.claude/skills/discover/niches/<niche>.md` — список аккаунтов в нише
2. Если ниша не указана (а есть имя клиента) — выбери по таблице ниже
3. Если список аккаунтов пустой — попроси Улю накидать 5–10 экспертов в этой нише и допиши файл

### Файлы ниш

Каждая ниша — отдельный файл `niches/<slug>.md` (например `niches/nalogi.md`, `niches/yur-biznes.md`, `niches/golf.md`). Slug = короткое имя ниши на латинице.

Если файла нет — создай шаблон с заголовком и попроси пользователя накидать аккаунты:
```
# Ниша: <название>
# Формат строки:
#   insta:<username>     # Instagram-аккаунт
#   yt:<channel_url>     # YouTube-канал (длинные ролики)
#   yts:<channel_url>    # YouTube Shorts (откроется /shorts)
```

## Алгоритм — пошагово

### Шаг 1. Разбери запрос
- **Ниша**: имя клиента или прямое название ниши
- **Период**: «за неделю» → 7 дней, «за месяц» → 30 дней (дефолт), «за квартал» → 90 дней
- **Sample size**: по умолчанию 30 постов на канал (медиана стабильная)

### Шаг 2. Прочитай файл ниши
`~/.claude/skills/discover/niches/<niche>.md` — там список `insta:`/`yt:`/`yts:` строк. Покажи Уле сколько аккаунтов сейчас в нише (одной строкой). Если меньше 3 — попроси добавить.

### Шаг 3. Запусти оркестратор
```bash
bash ~/.claude/skills/discover/scripts/run_niche.sh \
  ~/.claude/skills/discover/niches/<niche>.md \
  <DAYS> <SAMPLE_N> <INSTA_PAUSE>
```

Дефолты: `DAYS=30`, `SAMPLE_N=30`, `INSTA_PAUSE=35` (сек между Insta-запросами против rate-limit).

**Важно:** для ниши из 10 Insta-аккаунтов это займёт ~6 минут (10×35 сек паузы + по 3–5 сек на запрос). Запускать в фоне через `run_in_background: true`. Уле сразу сказать сколько примерно ждать: `~10 аккаунтов × 35 сек паузы = ~6 минут`.

stdout → собранный TSV по всем источникам. stderr → шапки `# username=... median=...`.

### Шаг 4. Парсинг и агрегация

Перечитай stdout. Каждая строка:
```
<platform>\t<source>\t<score>\t<metric>\t<median>\t<followers>\t<url>\t<date>\t<title>
```

- platform: `insta` / `yt` / `yts`
- metric: `likes` (Insta) или `views` (YouTube)
- source: username Insta или channel_url YouTube

Отфильтруй:
- score ≥ 3 (всё что ниже — не outlier)
- Уникальные URL (на случай дублей)

Сортируй по score убывающе. Возьми топ-15.

### Шаг 5. Балансировка
Из топ-15 не должно быть больше 3 роликов с одного аккаунта — иначе один автор задавит выдачу. Если у автора больше 3 в топе — оставь его 3 лучших, остальные подвинь дальше.

Также проверь: чтобы в финальном списке было минимум 30% Insta (если в нише вообще есть Insta-аккаунты) — Уля просила не перекашивать в YouTube.

### Шаг 6. Подтверждение цифр (только для YouTube)
Для YouTube топ-5 запусти `~/.claude/skills/research/scripts/check_video.sh <url>` — это вернёт реальный view_count (yt-dlp). Если совпадает — оставь. Если расходится (например baseline-скрипт вытянул кешированные цифры) — обнови.

Для Insta этот шаг пропускается: yt-dlp views на Insta не отдаёт, верим лайкам из gallery-dl.

### Шаг 7. Выдай результат + сохрани отчёт

Формат — см. ниже. После выдачи запиши markdown-отчёт в:
```
~/Documents/Reels-Research/discover/<niche>-<YYYY-MM-DD>.md
```

И обнови индекс `~/Documents/Reels-Research/INDEX.md` строкой:
```
| YYYY-MM-DD | discover <niche> <days>д | <клиент или —> | <топ-3 ссылок> | <число outlier'ов, медианы> |
```

## Формат выдачи

Заголовок одной строкой: `🎯 OUTLIER-СКАН: <ниша> · последние <N> дней`

Если был клиент: `· для <клиента>`.

Дальше — короткая статистика одной строкой:
`Сканировано: N аккаунтов · M постов · K outlier'ов (score≥3)`

Затем — топ-15 в формате (без code-fence, чтобы ссылки кликались):

`1.` `⭐⭐⭐⭐⭐` `🎬` **<заголовок ролика или первые слова описания>**
`🔗` https://прямая.ссылка
`👁` <metric> · автор · <followers> подписчиков · <platform>
`📊` Outlier <X>× от медианы <M> · опубликован <YYYY-MM-DD>
`📖` <2 предложения о чём ролик — берётся из title/description>
`🎯` УГОЛ ДЛЯ <клиент или «Reels»>: 1–2 предложения как переупаковать

Между роликами — пустая строка.

В конце одна строка:
`Полный отчёт: ~/Documents/Reels-Research/discover/<niche>-<дата>.md · Запустить ещё раз с другим периодом?`

## Режимы

- **«за неделю» / «week» / «7 дней»** → DAYS=7
- **«за месяц» / «month» / «30 дней»** → DAYS=30 (дефолт)
- **«за квартал» / «90 дней»** → DAYS=90
- **«глубоко»** → SAMPLE_N=50 (медиана надёжнее, но дольше)
- **«быстро»** → SAMPLE_N=15, INSTA_PAUSE=20 (риск rate-limit выше)
- **«только Insta»** → пропусти yt/yts строки в файле ниши
- **«только YouTube»** → пропусти insta строки
- **«добавь аккаунт <username> в <ниша>»** → допиши строку в niches/<ниша>.md (insta или yt — определи по URL)

## Чего никогда не делать

- ❌ **Не выдумывать цифры.** Только то что скрипт прислал.
- ❌ **Не пропускать шаг паузы на Insta** — 3 запроса подряд = rate-limit на всю сессию.
- ❌ **Не отдавать ролики со score < 3** даже если других нет — лучше честно сказать «в этой нише за период outlier'ов нет, попробуй другой период».
- ❌ **Не дублировать ролики** — дедуп по URL обязателен.
- ❌ **Не учить у автора где все ролики стабильно низкие** — если у канала median = 50 лайков, то 200 лайков это outlier по формуле, но не виральность. Если followers известны и score рассчитан от очень низкой медианы (< 100), помечай ⭐⭐⭐ максимум и предупреждай в УГОЛ-секции «маленький канал, проверь повторяемость».
- ❌ **Не запускать на пустой ниши** — попроси Улю наполнить файл сначала.

## Самопроверка перед выдачей

- [ ] Скрипт run_niche.sh отработал, есть stdout
- [ ] Все строки уникальны по URL
- [ ] Никаких score < 3 в финальном списке
- [ ] Не более 3 роликов от одного автора в топ-15
- [ ] Минимум 30% Insta (если ниша их содержит)
- [ ] Для топ-5 YouTube запущен check_video.sh — цифры подтверждены
- [ ] Отчёт сохранён в `~/Documents/Reels-Research/discover/`
- [ ] INDEX.md обновлён

## Известные ограничения

- **Insta rate-limit**: gallery-dl выдерживает ~3-4 быстрых запроса в сессии. Поэтому в `run_niche.sh` стоит пауза 35 сек между Insta. На 10 аккаунтов = ~6 минут. См. [[feedback-research-instagram]]
- **YouTube --flat-playlist** иногда возвращает view_count=NA для канальных страниц. Скрипт `scan_youtube.sh` сам делает fallback на полный режим (медленнее на ~2 сек/ролик), но это автоматика
- **Карликовые каналы** (median<100) дают раздутые score. Помечать осторожно

## Связь с другими скиллами

- `/research <тема>` — ищет по теме, агрегирует кросс-нишу. Использовать когда нужен срез под конкретный сюжет.
- `/discover <ниша>` — сканирует фиксированный список экспертов в нише за период. Использовать для «что взлетело у конкурентов клиента сейчас».
- После `/discover` имеет смысл взять 1-2 топ-ролика и через `/storyboard` сделать раскадровку для своего варианта.

## Еженедельный автоматический digest

`scripts/digest_all.sh` — оркестратор по **всем** заполненным нишам в `niches/*.md`. Запускается LaunchAgent'ом `com.rilsulya.digest.weekly` каждый понедельник в 8:00.

Что делает:
1. Обходит все `niches/*.md` (пропускает файлы без живых `insta:`/`yt:` строк)
2. Для каждой запускает `run_niche.sh` с периодом 7 дней
3. Сохраняет TSV в `~/Documents/Reels-Research/digest/_data/<DATE>/<niche>.tsv`
4. Через `render_digest.py` собирает HTML-отчёт `~/Documents/Reels-Research/digest/<DATE>.html`
5. Показывает macOS-уведомление и открывает HTML в Chrome

### Управление расписанием

```bash
# Запустить вручную сейчас (тот же сценарий что по расписанию)
bash ~/.claude/skills/discover/scripts/digest_all.sh 7 30 35

# Принудительный запуск через launchctl
launchctl start com.rilsulya.digest.weekly

# Проверить что агент загружен
launchctl list | grep digest

# Отключить временно
launchctl unload ~/Library/LaunchAgents/com.rilsulya.digest.weekly.plist

# Включить обратно
launchctl load ~/Library/LaunchAgents/com.rilsulya.digest.weekly.plist
```

### Артефакты digest
- `~/Documents/Reels-Research/digest/<DATE>.html` — финальный отчёт
- `~/Documents/Reels-Research/digest/_data/<DATE>/<niche>.tsv` — сырой TSV
- `~/Documents/Reels-Research/digest/_data/<DATE>/<niche>.log` — шапки + ошибки run_niche
- `~/Documents/Reels-Research/digest/_logs/<DATE>.log` — общий лог запуска
- `~/Documents/Reels-Research/digest/_logs/launchd.{out,err}.log` — лог самого launchd
